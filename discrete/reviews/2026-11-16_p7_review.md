## Findings so far

### 1. Typical mistakes: "the product is right only for coprime numbers, as in problem 7 (11, 5, 3)"
- **Severity:** MINOR (true as written, imprecise for three numbers). Not fixed yet.
- **What the page says:** «Արտադրյալը ճիշտ է միայն փոխադարձաբար պարզ թվերի դեպքում, ինչպես Խնդիր 7-ում ($11$,
  $5$, $3$)։»
- **What is right:** for two numbers `lcm(a,b) * gcd(a,b) = ab`, so the product equals the lcm exactly when
  `gcd(a,b) = 1`: the sentence is right for the pair `6, 4` it talks about. For three numbers the product equals
  `lcm(a,b,c)` exactly when they are pairwise coprime. `6, 10, 15` have no common divisor (gcd of all three is 1)
  and `lcm = 30`, not 900. The example in the bracket has three numbers, and the widget on the same page already
  says «զույգ առ զույգ փոխադարձաբար պարզ».
- **Fix planned:** none decided. Candidate: add «զույգ առ զույգ» before «փոխադարձաբար պարզ», after a glossary grep.

### 2. Widget `w-venn`, fraction line: a possible "≈ 58,00, which is not the exact 58"
- **Severity:** MINOR, **not confirmed**. Found by reading `fractionLine` in `p7.js`, not yet searched for.
- **What can happen:** when the fraction value is not an integer it is printed with two decimals after `\approx`,
  followed by «ինչը ճշգրիտ $r$-ը չէ». The difference between the fraction value and the exact count depends only
  on `M mod bc` and can be as small as `1/(bc)`; for `bc > 200` (say `b = 16`, `c = 15`) it can be below 0,005, so
  the two decimals could print the exact count itself. A search over all coprime `b, c <= 99` will show whether a
  reachable input does this.

### 5. Self-check 1, answer: "from every partition of {1,...,n-1}"
- **Severity:** MINOR. Not fixed.
