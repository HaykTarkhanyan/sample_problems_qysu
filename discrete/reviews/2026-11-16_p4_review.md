## Findings

### 1. Three key ideas, item 2: which method proves which property
- **Severity:** UNCLEAR. **Fixed.**
- **What the page said:** «Ինյեկտիվությունը հերքում ենք մեկ բախումով ..., սյուրյեկտիվությունը՝ մեկ բաց թողնված
  արժեքով։ Ապացուցում ենք հանրահաշվով ($f(x)=f(y)\Rightarrow x=y$, կամ $y=f(x)$-ի լուծումն ամեն $y$-ի համար) կամ
  խիստ մոնոտոնությամբ (խնդիրներ 6, 12)։» The second sentence has no object, so "we prove by algebra or by strict
  monotonicity" covers both properties named just before it.
- **What is right:** strict monotonicity proves injectivity only (`e^x` is strictly increasing and not onto `R`).
  The summary table and the old method box of problem 6 have it right. The converse (injective, hence monotone) is
  suggested nowhere on the page (all six places with «մոնոտոն» / «աճող» read).
- **Fix:** «Ինյեկտիվությունն ապացուցում ենք հանրահաշվով ($f(x)=f(y)\Rightarrow x=y$) կամ խիստ մոնոտոնությամբ,
  սյուրյեկտիվությունը՝ $y=f(x)$-ի լուծումով ամեն $y$-ի համար (խնդիրներ 6, 12)։» Same words, each method attached to
  its property, built like the sentence before it. Question R1.

### 2. «Ինչ պետք է հիշել», second bullet: "has an inverse if and only if bijective"
- **Severity:** UNCLEAR (borderline). **Fixed.**
- **What the page said:** «$f$-ն ունի հակադարձ այն և միայն այն դեպքում, երբ բիյեկտիվ է։»
- **What is right:** this is the theorem for `f: A -> B` with an inverse defined on all of `B`. The page never says
  so, and problem 5(գ) on the same page finds an inverse of `(x-2)/(x+3)` that is defined only for `x != 1`, while
  typical mistake 6 stresses that surjectivity depends on the codomain. Read with the informal definition of
  problem 5 (the inverse sends each output back), the true statement would be "if and only if injective".
- **Fix:** «$f:A\to B$ ֆունկցիան ունի հակադարձ $f^{-1}:B\to A$ այն և միայն այն դեպքում, երբ բիյեկտիվ է։» Symbols
  only; this is exactly what both brute-force checks test. Question R2.

## Check 8: the cross-line article probe

`logs/p4_xline.py` joins every line with the next one, lints the joined text and reports an article rule that fires
more often than on the two lines alone. Reproduced with my copy: on the old page 5 hits, 2 of them real («$f$-ն» /
«<em>ոչ</em>» and «$\{-1,-2\}$-ը» / «արտապատկերվում») and 3 at element boundaries; on the new page 4 hits, all at
element boundaries (a widget title or a box title followed by the first word of the next element, one button
followed by the next button); on the sheet 0.

**The idea is sound**: in HTML and in TeX a line break inside a paragraph is a space, and the lint reads one line
at a time, so it cannot see an article at the end of a line. To become a lint rule it needs:

1. blocks instead of line pairs: join the lines of one block of running text and nothing else. In HTML a block ends
   at a block-level tag (`div`, `p`, `li`, `h1`-`h6`, `button`, `summary`, `td`, `th`, `figcaption`, `option`), in
   TeX at a blank line, `\\`, `\item`, `\begin`, `\end` or a comment line. That removes every false alarm seen
   here (3 on the old page, 4 on the new one). Inline tags (`em`, `strong`, `a`, `span`) must stay transparent: one of the two real errors sat behind an
   `<em>` at the start of the next line;
2. positions instead of counts: the probe compares numbers of hits per rule, which can hide a new hit behind an old
   one on the same lines; a rule should report the joined hit whose article word and next word are on different
   lines, with the line number of the article;
3. the same block text for the other neighbour-based checks: the hint `negative-word-without-negative-verb` gives
   two false alarms on this page only because the verb is on the next line or behind a tag;
4. a run over all pages and sheets before it becomes an error (how many real hits, how many false), and two fixture
   lines in the lint's own tests, one real and one at an element boundary. Script files need no such pass (one
   string per line).
